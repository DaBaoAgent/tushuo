# tushuo 历史讲解片制作管线（定稿版）

- 版本：v1.0（2026-10-20）
- 基准片：`mongol-west-1`《蒙古第一次西征·讹答剌》v4
- 适用范围：60 秒、1080×1920 竖屏历史讲解片；新片沿用本管线的硬指标和检查口，只替换史料、口播、地图与分镜内容。
- 配套技能：`.claude/skills/tushuo-history-video/SKILL.md`
- 本片数据：`content/mongol-west-1/成片数据.md`

## 0. 交付硬指标

| 项 | 定稿值 |
|---|---|
| 画幅 / 帧率 | 1080×1920 / 30 fps，60.000 s |
| 视频编码 | H.264 High，yuv420p，约 6–7 Mb/s |
| 音频编码 | AAC LC，48 kHz，立体声，192 kb/s |
| 综合响度 | −16 LUFS 目标，实测 −16.2 LUFS |
| 真峰值 | ≤ −1.0 dBTP，目标 −1.5 dBTP |
| 黑帧 | `blackdetect d=0.1 pix_th=0.10` 未检出 |
| 交付 | 1080p 主片 + 720p 审阅版；`output/<slug>/QA.md` 记录规格与 QA |
| 画面检查 | HyperFrames `check` 0 error；文字对比度全部通过；关键帧人工审核 |

## 1. 目录与命名

```
content/<slug>/        事实底稿.md、分镜与口播.md、口播稿.txt、成片数据.md
films/<slug>/          HyperFrames composition（index.html、assets/、audio_meta.json、captions.json）
  renders/             仅旁白的原始渲染（gitignored）
  .hyperframes/        检查与渲染缓存（gitignored）
output/<slug>/         旁白、转写、音床、审核帧、成片、QA.md（gitignored）
docs/制作管线.md       本文件
```

- 一部片一个 slug；composition 的 `data-composition-id` 与 slug 一致。
- 成片统一命名：`<片名>.mp4`；审阅版：`<片名>-720p.mp4`。
- 审核帧目录：`output/<slug>/iteration-N/`；每次重大画面改动新开一个目录，不覆盖旧审核帧。
- 中间视频、原始渲染、旁白和音床不进 git；仓库只保留 composition、内容、工具、文档和可分发素材。

## 2. 流程总览

```
选题 / 史料 → 口播稿（用户审）→ dabao TTS → 词级转写 / 字幕
→ 分镜与 HyperFrames 画面 → check + 抽帧审核（用户审）
→ 全片渲染 → FFmpeg 混音 → QA → 交付 / 归档
```

三个用户关口：

1. 口播稿先给用户审；
2. 重大画面迭代先出 `iteration-N` 抽帧，用户确认后才全片渲染；
3. 用户说“定稿，跑成片”后，直接完成渲染、混音、QA，不再逐阶段请示。

## 3. 史料与口播

- 先写 `content/<slug>/事实底稿.md`：逐条列主张、一手 / 近同时代来源、现代研究、存疑边界；不要把不确定的数字写成定论。
- 再写 `content/<slug>/口播稿.txt`：60 秒片的目标旁白长度约 280–300 个汉字，实测 289 字合成 53.70 s，给片尾卡留约 6.3 s。
- 分镜写 `content/<slug>/分镜与口播.md`：时间码、画面、旁白、字幕、证物卡内容、不确定性标注。
- 画面必须常驻“地图为示意，非精确古地理”；人数、使者细节、围城时长、熔银等有争议处加小字或印章注记。

## 4. 配音（dabao 预设）

### 4.1 入口与权威参数

- 本项目入口：`tools\tts.cmd` → `tools\dabao_batch_tts.py`
- 服务：`vendor\gpt-sovits\tts_server.py`（127.0.0.1:9880）
  启动一律用 `wscript vendor\gpt-sovits\start-tts-server.vbs`（静默、幂等，不弹黑窗口）
- 权威参数：`vendor\gpt-sovits\tts_server.py` 的 `LOCKED`
- 参考音频 + 逐字稿：`vendor\gpt-sovits\ref_dabao3-1.wav` + 同文件的 `PROMPT`

| 参数 | 定稿值 |
|---|---|
| 切分 / 语速 | `cut1` / `speed_factor 1.0` |
| 采样 | `repetition_penalty 1.35`、`temperature 0.80`、`top_p 0.95`、`top_k 15`、`seed 666` |
| 分段 | ≤78 字；段前 30 ms、段间 20 ms |
| 音频 | 44.1 kHz 单声道，mp3 192 kbps |
| 音色 | GPT-SoVITS v2 底模 + 参考音频零样本克隆 |

```powershell
tools\tts.cmd --text-file content\<slug>\口播稿.txt --out output\<slug>\narration.mp3
```

- 历史/文言多音字先查 `docs/读音规范.md`；专名读音进 `tools\dabao_batch_tts.py`
  的 `SPEAK_FIXES`（词组级替换）。字幕保留原文，发音用替换字。
- **读音审计（改 `SPEAK_FIXES` 后必跑）**：用项目 venv 跑
  `tools/audit_pronunciation.py --slug <slug>`。它和 TTS 走同一条 G2P 路径
  （`SPEAK_FIXES` → 78 字分段 → 按标点切句 → G2PW），报告里的「实读」就是送进
  声码器的音节。必须逐条确认改成目标读音；**不能只测孤立词**——整句读对、切段后
  读错的情况真实发生过（张角、嫪毐），同音替换字也可能被上下文改读。
- 每段合成后核对 `output/<slug>/narration.json` 的 `chunks`：逐段时长、字数、语速；
  语速异常（远高于同字数段）说明有整句被吞。本片第 4 段就吞掉“志费尼记下：熔银灌眼。”
- 整句被吞的修复：单独合成该句（本片 2.06 s），按 20 ms 段间规则插回原段前，
  再重建整条旁白；用 medium ASR 回读确认句子进了文件。
- 定稿旁白不再重合成；画面迭代只改 composition。

## 5. 词级转写与字幕

本机没有 whisper.cpp，`npx hyperframes transcribe` 会失败；用项目封装：

```powershell
tools\transcribe_dabao.cmd --audio output\<slug>\narration.mp3 --out output\<slug>\transcript.json
python tools\hf_audio_meta.py --hyperframes films\<slug> `
  --audio output\<slug>\narration.mp3 --words output\<slug>\transcript.json --frame-id 1
```

- faster-whisper medium 专名同音错字很多（“讹答剌→厄答剌”“摩诃末→摩赫莫”）；
  ASR 只取时间，字幕文字必须对齐回口播稿原文。可用拼音 DP 对齐逐字时间。
- 不要把 TTS 的 `narration.json`（分段元数据）当词级 `transcript.json`。
- 字幕定稿样式：
  - 一句一条、去标点、≤15 字，不换行；
  - 白色 48px 粗体，紧贴文字的黑色圆角窄框（`rgba(0,0,0,.84)`，圆角 8px，
    内边距 14×24px）；
  - 硬切，显示时长按词级时间；不用底部通栏渐变；
  - 位置在画面下三分之一：`#caption-wrap { bottom: 440px; }`，
    框体约 y=1400–1480（画面 73–77% 高度），不要压到画面最下沿。
- 本片共 37 句。字幕数据落 `films/<slug>/captions.json`，composition 内联 `CAPS`
  同步保留。

## 6. HyperFrames 画面

### 6.1 composition 骨架

- 根节点：`data-width="1080"`、`data-height="1920"`、`data-fps="30"`、
  `data-composition-id="<slug>"`。
- 动画注册到唯一的 `window.__timelines["<slug>"]`，paused timeline；所有动画必须可 seek。
- 字体本地化：`films/<slug>/vendor/fonts/`（Noto Serif/Sans SC 可变字体），
  `vendor/gsap.min.js` 3.15；不依赖 CDN。
- 结构：`#map-stage > #map-svg`、`#vignette`、`#topline`、`#timeline-ui`、
  `#caravan`、`#commander`、`#card-1..3`、`#cause-dim/#cause-wrap`、字幕层、片尾卡。

### 6.2 首帧与地图

- 首帧直接进画面：不设黑场标题卡；地图、`450`、印章、字幕作为地图信息层出现。
- 手绘示意 SVG：地形（沙漠/绿洲/森林/雪山/高原/湖海）、城墙/城门/宣礼塔/穹顶、
  城镇/村落/商队骆驼；装饰性地图文字逐个 `<text>` 加 `data-layout-ignore`。
- `#map-stage` 用 `scale/x/y` 做缓慢推近；`transform-origin: 55% 45%`。
- 城市落点用 ring/dot + label；`“陷”`印在城破时盖章。

### 6.3 路线、商队与主帅卡（seek-safe）

HyperFrames 按时间 seek，**GSAP `onUpdate` 不能驱动逐帧定位的画面**。固定做法：

1. 用 `path.getPointAtLength(len * i / N)` 等距采样（N=48）路线；
2. 用普通 `tl.to(el, { x, y, duration, ease:"none" })` 逐段移动 DOM；
3. 路线显隐用静态虚线 + `linearGradient` 两个 stop 的 `offset` 动画（`attr`），
   与移动同起止、同 ease；
4. 到达终点后再出现箭头；卡/商队移动时虚线只画到其身后。

本片分工：

- 1218 商队：单独骆驼商队模型（3 峰骆驼 + 2 名随从 + 带篷货车 + 货包 + “蒙古商队”标签），
  沿“蒙古高原 → 讹答剌”移动；不使用成吉思汗卡。
- 1219 蒙古军：透明抠像成吉思汗（胸像 + 金环 + 半透明“主帅 成吉思汗”标签），
  只用于讹答剌 → 布哈拉 → 撒马尔罕两段；两段分别 25.2 s / 33.75 s 起步。

### 6.4 证物卡（定稿参数）

| 项 | 定稿值 |
|---|---|
| 比例 / 尺寸 | 16:9，400×225 px |
| 位置 | `left:280px; top:100px`，中心 x≈480，钦察草原上方；底边 y=325 |
| 背景 | `rgba(23,21,18,.84)` + `backdrop-filter: blur(2px)` |

| 引文 | 25px（证物 03 短句 34px），`#f4ead6` |
| 出处 | 13px，`#b9a887`，一行 |
| 印章 | 58px 双线圆印，右下 |
| 入场 | 从上方 `y:-390` 滑入 0.6 s |
| 退场 | 位移 0.45 s + 透明度 0.16 s 快速淡出，避免扫过顶部栏 |

- 引文按语义分两行（“携金、银、／貂皮、丝绸……”“苏丹杀使者，／剃去随行者的胡须。”），
  减少卡片底部留白；文字块在卡片内垂直居中。

### 6.5 其它画面

- 顶部栏：`图说战史 · 第一次西征` + 章节号，y=32。
- 时间轴在左侧，10.15–42.35 s 可见。

### 6.6 检查与审核口

```bash
cd films/<slug>
npx --yes hyperframes lint
npx --yes hyperframes check
npx --yes hyperframes snapshot --at 0.5,3.3,6.5,17,25.8,32,34.5,45.5,50.5 --no-end --no-browser-gpu -o output/<slug>/iteration-N
```

- `check` 必须 0 error；1 条“文件过长”warning 和行军虚线被误判为 connector 的
  info 可接受，其他 warning/info 逐条解释。
- 对比度必须全部通过；装饰性地图文字用 `data-layout-ignore`，卡片标签外伸用
  `data-layout-allow-overflow`。
- 审核帧交付：`contact-sheet-key.jpg` + 10 张单帧 + `review.md`；
  用户确认后才全片渲染。

## 7. Windows 全片渲染

系统 Chrome（本机 155）+ SwiftShader，单 worker，低内存模式：

```bash
npx --yes hyperframes render -o "renders/<slug>-v4.mp4" \
  --no-browser-gpu --workers 1 --low-memory-mode --quality delivery --quiet
```

若卡在 “Checking browser” / 浏览器安装：

1. 用 `Get-CimInstance Win32_Process -Filter "Name='node.exe'"` 找
   `hyperframes render` 的子进程，精确 `Stop-Process`；
2. 确认没有渲染进程后，删 `~/.cache/hyperframes/.chrome.install.lock` 和
   `.chrome-staging-*`；不要删整个 chrome 缓存；
3. 重新指向系统 Chrome 再渲染。

本片原始渲染：`films/mongol-west-1/renders/mongol-west-1-v4.mp4`，60 s，
1080×1920，30 fps，48 MB。原始渲染只含旁白，不含音床。

## 8. 混音（FFmpeg）

音床 `output/<slug>/bed.wav` 为 60 s 原创 NumPy 合成（无外部采样）。混音固定口径：

```bash
ffmpeg -hide_banner -loglevel error -y \
  -i "renders/<slug>-v4.mp4" -i "output/<slug>/bed.wav" \
  -filter_complex "[0:a]aresample=48000,pan=stereo|c0=c0|c1=c0[vo];[1:a]volume=0.9[bed];[vo][bed]amix=inputs=2:duration=first:normalize=0,loudnorm=I=-16:TP=-1.5:LRA=11[a]" \
  -map 0:v -map "[a]" -c:v copy -c:a aac -b:a 192k -ar 48000 \
  -movflags +faststart -t 60 "output/<slug>/<片名>.mp4"
```

- 视频流 `-c:v copy`，只重编码音频；
- `loudnorm` 会把采样率升到 192k，最终必须显式 `-ar 48000`；
- 目标 −16 LUFS / TP −1.5；本片实测 −16.21 LUFS / −1.35 dBTP；
- 不要用 `-shortest` 截断音床；用 `-t 60` 固定片长。

## 9. QA 与交付

```bash
F="output/<slug>/<片名>.mp4"
ffprobe -v error -show_entries format=duration,size,bit_rate \
  -show_entries stream=index,codec_type,codec_name,width,height,r_frame_rate,sample_rate,channels \
  -of json "$F"
ffmpeg -v error -xerror -i "$F" -f null -          # 全片解码
ffmpeg -i "$F" -vf "blackdetect=d=0.1:pix_th=0.10" -an -f null -  # 黑帧
ffmpeg -i "$F" -af loudnorm=print_format=json -f null -           # 响度/峰值
```

- 另出 720p 审阅版：`ffmpeg -i "$F" -vf scale=720:1280 -c:v libx264 -crf 23 -c:a copy ...`。
- 抽 0.5 / 6.5 / 17 / 32 / 50.5 s 帧复核卡片、字幕、片尾。
- 写 `output/<slug>/QA.md`：文件路径、大小、SHA256、规格、黑帧、响度、峰值、
  TTS / 音床 / 字幕 / 检查 revision、限制与渲染备注。
- 交付前做一次独立 verification 代理复核（规格、解码、黑帧、响度、抽帧、
  720p、视频流一致性），PASS 才交付；若代理未返回，如实写明，不把主流程自检
  当作独立结论。

### 9.1 发布信息（全管线统一口径）

1. 第一行标题 **≤25 个字（含标点）**，**两段式**：前半句钩子 + 后半句具体后果/承诺，

## 11. 踩坑清单

- **TTS 整句被吞**：6.2 字/秒守卫不能保证句子完整；逐段回读，缺句单独合成再插回。
- **GSAP onUpdate 不可 seek**：所有逐帧定位改用路径采样 + `x/y` 关键帧。
- **遮罩揭示失败**：改用 `linearGradient` stop offset 动画。
- **负 z-index** 会被 lint 拒绝；用兄弟层做暗角。
- **left/top 动画** 会被 lint 拒绝（`gsap_non_transform_motion`）；用 `x/y` + 负 margin。
- **多次 fromTo** 加 `immediateRender:false`，避免后续 tween 抢跑。
- **字幕硬切** 用 0.01 s；0.07 s 会在截图里抓到灰态。
- **卡片压地名**：4:3 的 400×300 会碰到“钦察草原”，16:9 的 400×225 才留出约 100px。
- **顶部栏与证物标签**：证物卡标签在 y=72–102，顶部栏必须上移到 y=32。
- **Chrome 安装锁**：渲染卡 “Checking browser” 时清 `.chrome.install.lock` 与
  `.chrome-staging-*`，并杀掉子进程。
- **loudnorm 采样率**：最终编码显式 `-ar 48000`；视频流 copy，不要重编码。

## 12. 不要做

- 不要用 HyperFrames 内置 TTS（Kokoro / HeyGen / ElevenLabs / Gemini）；
- 不要把 TTS 分段 `narration.json` 当词级转写；
- 不要把旁白、音床、原始渲染、中间视频提交进 git（`.gitignore` 已覆盖）；
- 不要把 `output/` / `renders/` / `.hyperframes/` 缓存提交进 git；
- 不要在未抽帧审核的情况下直接全片渲染；
- 不要用 `onUpdate` 或非 transform 属性驱动需要逐帧定位的画面。
